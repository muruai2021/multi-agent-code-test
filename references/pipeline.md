## 详细阶段说明

### Phase 1: 任务分析

**主编操作**:
1. 解析测试请求，提取关键信息：
   - 需要测试的文件列表
   - 代码语言和框架
   - 已有测试覆盖情况
   - 目标覆盖率
2. 确定需要生成的测试类型
3. 制定测试计划

**测试类型选择矩阵**:

| 代码类型 | 推荐测试类型 |
|----------|-------------|
| 业务逻辑函数 | Unit Test |
| API 端点 | Unit Test + Integration Test |
| 用户界面 | Unit Test + E2E Test |
| 安全相关 | Security Test |
| 高并发模块 | Performance Test |

### Phase 2: 并行测试生成

**执行策略**: 所有专业 Agent 同时开始生成测试

**Agent 调度矩阵**:

| 测试类型 | 必须调度的 Agent |
|----------|-----------------|
| 基础测试套件 | Unit Test Generator |
| API 测试 | + Integration Test Generator |
| Web 应用 | + E2E Test Generator |
| 安全敏感模块 | + Security Test Generator |
| 高性能模块 | + Performance Test Generator |

**并发控制**:
- 最大并发 Agent 数: 6
- 单个 Agent 超时: 5 分钟
- 全部 Agent 超时: 10 分钟

### Phase 3: 测试汇总

**主编操作**:
1. 收集所有 Agent 生成的测试文件
2. 合并重复的测试用例
3. 统一测试文件结构
4. 生成测试套件索引

**合并规则**:
- 同一函数只保留最高质量的测试
- 相同断言合并
- 互补的边界测试保留

### Phase 4: 覆盖率分析

**Coverage Analyzer 操作**:
1. 使用对应语言的覆盖率工具运行测试
2. 生成覆盖率报告
3. 识别未覆盖的代码行
4. 标记高风险未测试区域

### Phase 5: 输出最终报告

**报告内容**:
1. 测试统计摘要
2. 生成的测试文件列表
3. 覆盖率报告
4. 高优先级测试缺口
5. 下一步建议

## 测试优先级

### P0 - Critical (必须测试)
- 认证/授权逻辑
- 支付/交易逻辑
- 数据验证
- 安全相关

### P1 - Important (应该测试)
- 业务逻辑
- API 端点
- 错误处理
- 边界条件

### P2 - Standard (标准测试)
- 辅助函数
- 数据转换
- 工具类

### P3 - Nice to Have (可选测试)
- 注释覆盖
- 代码风格
- 文档完整性

## 错误处理

| 场景 | 处理策略 |
|------|----------|
| 单个 Agent 超时 | 标记为「部分完成」，继续其他 Agent |
| 部分 Agent 失败 | 已完成的测试保留，报告失败部分 |
| 全部 Agent 失败 | 返回错误，提示用户检查代码语法 |
| 文件读取失败 | 跳过该文件，报告无法测试 |

## 测试质量标准

### 单元测试标准
- 每个测试单一断言原则
- 测试名称描述清晰
- Arrange-Act-Assert 结构
- Mock 外部依赖
- 包含正向和负向用例

### 集成测试标准
- 使用真实数据库（测试环境）
- 每个测试独立运行
- 适当的 setup/teardown
- 测试真实用户场景

### E2E 测试标准
- 模拟真实用户操作
- 跨浏览器兼容
- 适当的超时设置
- 截图/录像失败记录
